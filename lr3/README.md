# ЛР3 — декомпозиція системи обліку замовлень служби доставки їжі на сервіси

Ядро з ЛР2 розділено на три сервіси з власними даними та шлюз. Доменні правила перенесено без змін
(змінився лише тип помилки: `DomainError` замість `Error`).

| Процес       | Порт | Володіє даними                         | Взаємодія                                                    |
|--------------|------|----------------------------------------|--------------------------------------------------------------|
| gateway      | 3000 | —                                      | єдина точка входу `/api/*`, проксіює запити сервісам          |
| orders       | 3001 | Замовлення, Клієнт                     | синхронно викликає restaurants; публікує `order.confirmed`; споживає `delivery.started` |
| restaurants  | 3002 | Ресторан                               | відповідає на синхронні запити                               |
| delivery     | 3003 | Кур’єр, Доставка, черга диспетчера     | споживає `order.confirmed`; публікує `delivery.started`      |

Кожен сервіс зберігає дані у власному сховищі (в пам’яті свого процесу), спільної бази даних немає.
Контракти: `contracts/openapi/*.yaml`, `contracts/events/*.schema.json`.

## Запуск
```
npm install
npm test              # домен, сценарії, архітектура, контракти, інтеграція
npm run build
npm run start:all     # усі чотири процеси; шлюз: http://127.0.0.1:3000/api
npm run demo          # експеримент з вимкненими сервісами (запускає процеси сам)
```
Порти можна змінити змінною `BASE_PORT` (наприклад, `BASE_PORT=4000`).

## Приклади запитів
```
curl http://127.0.0.1:3000/api/health
curl -X POST http://127.0.0.1:3000/api/orders -H "Content-Type: application/json" -d "{\"id\":\"o1\",\"customerId\":\"cust-1\",\"restaurantId\":\"rest-1\",\"deliveryAddress\":\"Київ\",\"items\":[\"Борщ\"]}"
```
Тестові дані: клієнт `cust-1`, ресторани `rest-1`, `rest-2`, кур’єри `courier-1`, `courier-2`.
